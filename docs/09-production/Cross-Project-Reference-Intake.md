## Recommended exchange contract

Use references to canonical objects instead of copying entire repositories. A candidate exchange envelope should identify its originating project, immutable source locator and hash, object type, revision, evidence lane, applicability/state, target owner, dependencies and acceptance status. Suggested object types are source, claim, state, artifact, task and validation result. This is a proposal, not an implemented bridge.

Review owner-authored requests separately from assistant-generated suggestions. Keep conceptual artwork and unconventional hypotheses visibly separate from established measurements. Before promoting a candidate, check whether the current canonical owner already implements it; record amendments rather than overwriting newer work.
