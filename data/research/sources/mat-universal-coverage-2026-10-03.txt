# MAT UNIVERSAL COVERAGE REQUIREMENT
## Elements 0000–0118, Future Elements, Nature and Beyond

This requirement is mandatory for the MAT architecture.

MAT must **not** be built as a database limited to the conventional periodic table.

The periodic table is one important coordinate system inside MAT, but it does not represent all matter, structures, processes, fields, biological systems, environments, transformations or phenomena found in nature.

---

## 1. CANONICAL RANGE

Use:

```text
MAT:0000 = Origin / Foundation Reference
MAT:0001 = Hydrogen
MAT:0002 = Helium
...
MAT:0118 = Oganesson
```

`MAT:0000` is not chemical element zero.

It is the foundation/reference state from which MAT's coordinate, evidence, measurement and comparison systems inherit.

---

## 2. ALL CONFIRMED ELEMENTS MUST USE THE SAME MAT TEMPLATE

Every element from:

```text
MAT:0001
through
MAT:0118
```

must inherit the Universal MAT Element Schema.

Do not create a detailed Hydrogen system and then use simplified records for later elements.

Hydrogen is the first validation implementation.

It is the **reference implementation for the architecture**, not an exception.

Every element must be capable of representing the same applicable categories.

# 5. DO NOT FORCE INAPPLICABLE DATA

Universal template does **not** mean pretending every property applies universally.

For example:

```text
mechanical hardness of an isolated atom
```

should not receive an invented value.

Instead:

```text
property_status: NOT_APPLICABLE
```

Likewise a property may belong to:

```text
ELEMENT
ISOTOPE
ATOM
ION
MOLECULE
PHASE
BULK_MATERIAL
SAMPLE
```

rather than directly to the abstract element.

# 6. ELEMENTS BEYOND 118

MAT must not end structurally at Oganesson.

Support:

```text
Z = 119+
```

as research candidates.

Use statuses such as:

```text
THEORETICALLY_PREDICTED
NUCLIDE_PREDICTED
SYNTHESIS_TARGET
EXPERIMENT_SEARCH
UNCONFIRMED_SIGNAL
CANDIDATE
CONFIRMED
RETRACTED
```

Never label a predicted element as experimentally discovered without appropriate confirmation.

Potential objects may therefore use:

```text
MAT:ELEMENT:CANDIDATE:0119
MAT:ELEMENT:CANDIDATE:0120
...
```

or an equivalent future-proof schema.

The storage system must not impose:

```text
MAX_ATOMIC_NUMBER = 118
```

as a permanent architectural limit.


# 25. IMPLEMENTATION REQUIREMENT FOR CODEX

When implementation begins:

1. Inspect the existing MAT repository.
2. Find whether element schemas are duplicated or inherited.
3. Create/refactor toward a Universal MAT schema.
4. Ensure MAT:0001 Hydrogen uses it.
5. Ensure the same schema can instantiate MAT:0002–MAT:0118.
6. Do not fabricate missing scientific data.
7. Missing data should receive explicit status fields.
8. Ensure future element candidate IDs are supported.
9. Ensure non-element MAT objects can use the same foundational architecture.
10. Add tests proving MAT does not have a hard 118-object architectural limit.
